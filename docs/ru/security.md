# Безопасность

SSHKipper хранит пароли, ключи и секреты 2FA многих серверов. Расширение получает только то, что нужно его вкладам, и
пользователь видит это до установки. Здесь — что приложение гарантирует для любого расширения, затем что получает
каждый вид вклада и чего он не получает никогда.

## Что гарантирует приложение

- **Ничего из расширения не выполняется в приложении.** Серверные скрипты выполняются на сервере; программа —
  отдельный процесс на этом Mac с чистым окружением. Страницы и экраны — JSON, который рисует приложение: ни HTML, ни
  скриптов в виде.
- **Расширения устанавливает пользователь**, из файла или папки; сначала приложение показывает словами, что расширение
  добавляет, его права, где выполняется его код (у программы — её команду и то, что она работает с правами
  пользователя без песочницы), что оно меняет, инструменты AI и блоки автоматизаций. Агенты и документы устанавливать
  расширения не могут. Обновление, которое добавляет право или вклад, ставится выключенным, пока пользователь его не
  включит; выключенное пользователем остаётся выключенным.
- **Доверие показывается, а не подразумевается.** Расширение из любого файла — «Автор не проверен». «Проверено
  SSHKipper» — только расширение из подписанной библиотеки SSHKipper, файлы которого совпадают с записью библиотеки; и
  только тогда приложение учитывает его утверждения о чтении (`readCommands` движка базы).
- **Целостность.** Каждый файл установленного расширения хеширован и сверяется снова перед каждым запуском его
  программы: изменённый, добавленный или удалённый файл останавливает его, пока пользователь не разрешит снова.
- **Учётные данные остаются в приложении.** Ни одно расширение не видит пароль сервера, ключи или коды 2FA, документ
  или секреты другого расширения. Серверные скрипты выполняются по сессии приложения; программа просит приложение
  (`host.exec`, `host.forward`) и может назвать только серверы и узлы своих текущих вызовов и открытых экранов.
- **Секреты — по запросу.** Секретная настройка или поле хранится зашифрованным и выдаётся только своему расширению:
  серверному скрипту — файлом 0600 в личной папке, которая удаляется после запуска (`SK_SECRET_<KEY>`), никогда в
  командной строке и никогда в контейнер; программе — на `host.secret` / `host.nodeSecret` или в `settings` её
  собственного узла (хранилища, источники), но никогда в `context.settings` страницы.
- **Значения проверяются.** Параметры действий, инструментов и блоков проверяются по их `params` (типы, варианты,
  `pattern` целиком) до запуска обработчика; неизвестные ключи отбрасываются. Ответы тоже: виды — по схеме, импорт — до
  любых изменений, вывод консоли — по её пределам.
- **Изменения спрашиваются.** Действия `change` и `danger` сначала спрашивают пользователя; вызовы агента проходят
  через режим AI сервера и подтверждения, как его собственные команды; шаги автоматизаций — через разрешение
  автоматизации; запросы движка базы — через режим узла (Production спрашивает, «Только чтение» отказывает).
- **Права проверяются** там, где приложение стоит на пути: `exec` (серверные скрипты, `host.exec`), `sudo`, `secrets`
  (`host.secret`, секретные настройки и поля), `store`, `notify`, `forward` (`host.forward`) и `oauth` (`host.oauth`) —
  запрос без своего права завершается ошибкой `-32001`. `network` не проверяется: это заявление автора.
- **Программы завершаются вместе с дочерними процессами.** Программа работает в своей группе процессов: когда
  расширение выключили, обновили, удалили, оно простаивало десять минут, заблокировался документ, для которого оно
  работало (все программы — когда не осталось открытых документов), или приложение завершается, — группе SIGTERM, тому,
  что осталось, через несколько секунд — SIGKILL. `runtime.env` не может задать переменные, которые загружают код
  извне расширения (`NODE_OPTIONS`, `DYLD_*`, `LD_*`, `PYTHONSTARTUP`, `*_OPTIONS`…).
- **Пределы.** Тайм-ауты останавливают на сервере всю группу процессов; вывод ограничен (8 МБ от скрипта, 16 МБ на
  строку JSON-RPC); виды ограничены (400 блоков, 2 МБ); закрытые страницы останавливают свои вызовы.

## Что получает каждый вклад

| Вклад | Получает | Не получает никогда · проверяет приложение |
|---|---|---|
| `service`, `tools`, `automation` (серверные скрипты) | запрос на stdin, свои настройки, свои секретные настройки файлами | учётные данные сессии; секреты внутри контейнера. Выполняется только там, где служба включена, или когда пользователь открыл, нажал, разрешил или поставил в расписание; `detect` сам проверяет каждый подключённый сервер, только если пользователь это отметил, — и никогда через sudo |
| обработчики и блоки программы | `context` вызова (сервер, настройки, элемент, узел), `host.exec` на сервере вызова | серверы чужих вызовов; между вызовами — ничего, кроме того, что показывают её открытые экраны |
| `database` | `127.0.0.1` и порт, проброшенный приложением по своей SSH-сессии, имя базы для TLS, **пароль одной базы**, которую он открывает | документ, ключи, пароли других баз. Отдельный процесс; останавливается, когда блокируется последний документ. У непроверенного расширения каждый запрос — изменение (Production спрашивает с полным текстом, «Только чтение» отказывает) |
| `storage` | поля своего узла, секретные — текстом; `host.forward` к цели за сервером, к которому пользователь привязал узел; `host.oauth`, пока пользователь входит | поля и секреты другого узла; проброс для узла не из вызова; вход, который пользователь не начинал. Токен обновления хранится секретом узла; `digest` загрузки сверяется |
| `source` | поля своего узла, секретные — текстом | документ: найденные узлы в него не пишутся; ключам серверов из источника приложение не доверяет — при первом подключении ключ показывается; фильтры пользователя применяет приложение |
| `nodeType`, `screen` | настройки и привязки своего узла; `host.nodeSecret` секретных полей своего типа; `host.exec` на сервере, к которому привязан узел; `host.open`, `host.ask` | узлы, которых он не видит (чужой id, угаданный, узел другого расширения); пароль, ключ или 2FA документа (запись, общая с ними, — отказ). Команда терминала вводится только после «да» пользователя в вопросе, где видна она и оценка политики команд; не больше 5 открытий за 10 с; вопросы подписаны именем расширения |
| `import` | байты и имя файла, который выбрал пользователь (≤ 8 МБ или `maxSizeMB`) | путь к файлу и что-либо ещё с диска. Ответ проверяется до любых изменений; пароли и ключи отделяются и импортируются, только если пользователь согласится |
| `console` | адрес и логин узла; то, что набирает пользователь; размер терминала | пароль или ключ. Вывод ограничен (≈ 1 МБ на кусок, 2 МБ/с после всплеска), OSC 52 спрашивается, как у любого сервера, данные сессии, которую программа не открывала, отбрасываются |
| `ai` | запрос после маскировки и политики приложения (что сессия может показать модели, Production, скрытое от AI); секретные поля своего профиля, хранящиеся в связке ключей | право выполнить инструмент: вызов инструмента в ответе проходит через правила режима AI и подтверждения пользователя. Ответ больше 4 МБ — ошибка |

## Что «по возможности»

- Программа — это программа с правами пользователя на этом Mac: `network` (и то, что она делает с файлами) — заявление,
  которое читает пользователь, а не песочница. То, что программе дали, — пароль базы, токен хранилища, ключ API
  профиля, — она может отправить куда угодно. Устанавливайте программы от тех, кому доверяете, — как любое приложение.
- Серверный скрипт выполняется с правами пользователя подключения (и root через `sudo -n`, где разрешено): он может
  делать на сервере то же, что этот пользователь. Прочитайте скрипты расширения, прежде чем дать ему `sudo`.
- Агент может вызывать инструменты расширения только в рамках режима AI сервера; инструмент, который что-то меняет,
  безопасен ровно настолько, насколько честен его `risk`. Проверяйте `risk` при установке расширения.
- `sshkipper-ext mcp` без `--allow-changes` выполняет только обработчики, которые манифест использует для чтения, и
  читающие методы — это защита от случайного запуска объявленного изменения агентом, а не песочница: код, который
  выполняется, агент пишет сам.

## Авторам расширений

- Задайте `pattern` каждому текстовому параметру, который доходит до скрипта; берите каждую переменную в кавычки;
  никогда не делайте `eval` входных данных.
- Не печатайте секреты: stderr уходит в журнал расширения, stdout — на страницы, моделям и в запуски автоматизаций.
- Для значений в командах `host.exec` используйте `quote()` (TypeScript).
- Просите минимум: без `sudo`, если обработчик может обойтись; `sudo: never` у обработчиков, которые читают; без
  `forward` и `oauth`, если хранилище ими не пользуется.
- Держите выданные секреты в памяти: не пишите токен хранилища или пароль базы в `SK_DATA` и в журнал.
- Драйвер базы: открывайте узел «Только чтение» только для чтения, где движок это умеет (`connection.readOnly`), а
  `tableData` и запросы `readOnly` выполняйте на соединении только для чтения.
- Не загружайте код во время работы (`curl … | sh`, плагин, скачанный при запуске): выполняться должно то, что
  разрешил пользователь.
