# Безопасность

SSHKipper хранит пароли, ключи и секреты 2FA многих серверов. Модуль получает только то, что нужно для его работы, и
пользователь видит это до установки.

## Что гарантирует приложение

- **Ничего из модуля не выполняется в приложении.** Серверные скрипты выполняются на сервере; модуль-программа —
  отдельная программа с чистым окружением. Страницы — JSON, который рисует приложение: ни HTML, ни скриптов в
  странице.
- **Модули устанавливает пользователь**, из файла или папки; сначала приложение показывает словами права, где
  выполняется код модуля (у модуля-программы — её команду и то, что она работает с правами пользователя без
  песочницы), что он меняет, инструменты AI и блоки автоматизаций; имя автора показано как непроверенное («Автор не
  проверен»). Агенты и документы устанавливать модули не могут. Обновление не включает модуль, который пользователь
  выключил.
- **Серверный код выполняется там, где разрешил пользователь.** Скрипты серверного модуля выполняются только там, где
  его служба включена для сервера, — когда пользователь открывает его страницу, нажимает его действие, разрешает его
  инструмент AI или ставит его блок в автоматизацию. Его `detect` сам проверяет каждый подключённый сервер, только если
  пользователь отметил это в вопросе установки (или позже в меню «⋯» модуля), — и никогда через sudo.
- **Целостность.** Каждый файл установленного модуля хеширован; изменённый файл выключает модуль, пока пользователь не
  разрешит его снова.
- **Учётные данные остаются в приложении.** Модуль никогда не видит пароль сервера, ключи или коды 2FA: серверные
  скрипты выполняются по сессии приложения; модуль-программа просит приложение (`host.exec`) и может назвать только
  серверы вызова.
- **Секреты — файлами.** Секретная настройка доходит до серверного скрипта файлом 0600 в личной папке, которая
  удаляется после запуска (путь — в `SK_SECRET_<KEY>`), и никогда — в командной строке; в `context.settings` её нет; в
  контейнер она не передаётся вовсе.
- **Значения проверяются.** Параметры действий, инструментов и блоков проверяются по их `params` (типы, варианты,
  `pattern` целиком) до запуска обработчика; неизвестные ключи отбрасываются.
- **Изменения спрашиваются.** Действия `change` и `danger` сначала спрашивают пользователя; вызовы агента проходят
  через режим AI сервера и подтверждения, как его собственные команды; шаги автоматизаций — через разрешение
  автоматизации.
- **Права проверяются** там, где приложение стоит на пути: обработчики серверного модуля без `exec`, `host.exec` без
  `exec`, `host.secret` без `secrets`, `host.store` без `store` завершаются отказом; секретные настройки без `secrets`
  не предлагаются. `network` не проверяется: это заявление автора.
- **Программы завершаются вместе с дочерними процессами.** Программа модуля-программы работает в своей группе
  процессов: когда модуль выключили, обновили, удалили, он простаивал десять минут, заблокировался документ, для
  которого она работала (все программы — когда не осталось открытых документов), или приложение завершается, — группе
  SIGTERM, тому, что осталось, через несколько секунд — SIGKILL. `runtime.env` не может задать переменные, которые
  загружают код извне модуля (`NODE_OPTIONS`, `DYLD_*`, `LD_*`, `PYTHONSTARTUP`, `*_OPTIONS`…).
- **Пределы.** Тайм-ауты останавливают на сервере всю группу процессов; вывод ограничен (8 МБ от скрипта, 16 МБ на
  строку JSON-RPC); виды ограничены (400 блоков, 2 МБ); закрытые страницы останавливают свои вызовы.

## Что «по возможности»

- Модуль-программа — программа с правами пользователя на этом Mac: `network` (и то, что она делает с файлами) — это
  заявление, которое читает пользователь, а не песочница. Устанавливайте программы от тех, кому доверяете, — как любое
  приложение.
- Серверный скрипт выполняется с правами пользователя подключения (и root через `sudo -n`, где разрешено): он может
  делать на сервере то же, что этот пользователь. Прочитайте скрипты модуля, прежде чем дать ему `sudo`.
- Агент может вызывать инструменты модуля только в рамках режима AI сервера; инструмент, который что-то меняет,
  безопасен ровно настолько, насколько честен его `risk`. Проверяйте `risk` при установке модуля.

## Авторам модулей

- Задайте `pattern` каждому текстовому параметру, который доходит до скрипта; берите каждую переменную в кавычки;
  никогда не делайте `eval` входных данных.
- Не печатайте секреты: stderr уходит в журнал модуля, stdout — на страницы, моделям и в запуски автоматизаций.
- Для значений в командах `host.exec` используйте `quote()` (TypeScript).
- Просите минимум: без `sudo`, если обработчик может обойтись; `sudo: never` у обработчиков, которые читают.
- Не загружайте код во время работы (`curl … | sh`): выполняться должно то, что разрешил пользователь.
