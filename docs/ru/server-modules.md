# Модули на сервере

`"runtime": {"kind": "server"}` — каждый обработчик это POSIX-скрипт `sh` модуля, который приложение выполняет **на
сервере**, через уже открытую SSH-сессию: через бастионы и 2FA пользователя, в контейнере, если служба живёт в нём,
через `sudo -n`, где это разрешено. На сервер ничего не устанавливается, на Mac ничего не запускается.

## Что получает скрипт

| | |
|---|---|
| stdin | запрос в JSON: `{"handler", "input", "context": {"server", "container", "settings", "item", "locale", "sdk", "app"}}` |
| `SK_INPUT_<KEY>` | каждое значение `input` (числа — текстом, логические — `1`/`0`, списки и объекты — в JSON) |
| `SK_SETTING_<KEY>` | каждая несекретная настройка подключения |
| `SK_SECRET_<KEY>` | **путь** к файлу 0600 с секретной настройкой (нужно право `secrets`); `sk_secret ключ` печатает её |
| `SK_ITEM_ID` | id строки — для действий `on: item` и страниц строки |
| `SK_CONTAINER` | имя контейнера, если скрипт выполняется в нём |
| `SK_AUTOMATION` | `1`, если скрипт выполняется как блок автоматизации |
| `SK_TMP` | личная папка 0700, удаляется после запуска (она же рабочий каталог) |
| `SK_HANDLER`, `SK_MODULE`, `SK_SDK`, `SK_LOCALE` | какой обработчик, какой модуль, `1`, `ru`/`en`/… |

Значения приходят по сессии, а не в командной строке: другие пользователи сервера не видят их в `ps`.

## Прелюдия

Определена перед вашим скриптом ([spec/prelude.sh](../../spec/prelude.sh)), потому что `jq` есть не на каждом сервере:

```sh
sk_json_string "$name"                 # "a \"quoted\" name"
sk_json_kv state active pid 1234       # {"state":"active","pid":"1234"}
sk_fail "no such queue: $q"            # в stderr, выход с кодом 1 — эту строку увидит пользователь
sk_has supervisorctl || sk_fail "supervisor isn't installed"
sk_file scripts/lib.awk > "$SK_TMP/lib.awk"   # другой файл из scripts/ модуля
sk_secret token                        # секретная настройка «token»
```

## Вывод

- `output: "json"` (по умолчанию) — напечатайте **одно** значение JSON. Соберите его через `printf` и `sk_json_string`
  или через awk:

  ```sh
  printf '{"queues": ['
  first=1
  for q in $(redis-cli --raw keys 'queues:*'); do
    [ $first = 1 ] || printf ','; first=0
    n=$(redis-cli --raw llen "$q")
    printf '{"name": %s, "waiting": %d}' "$(sk_json_string "${q#queues:}")" "$n"
  done
  printf ']}'
  ```

- `output: "text"` — stdout строкой; `"lines"` — массив строк.
- stderr — это журнал: его хранит журнал модуля в приложении; при сбое сообщением становится его **последняя строка**.
- Ненулевой код выхода — сбой. `timeout` (по умолчанию 30 с) останавливает на сервере всю группу процессов; закрытие
  страницы — тоже.

## Sudo

Не вызывайте `sudo` в скрипте (он будет ждать пароль). Скажите, что нужно обработчику:

- `"sudo": "auto"` (по умолчанию) — через `sudo -n`, когда у сервера включено «Использовать sudo -n» и у модуля есть
  право `sudo`; если sudo всё равно просит пароль, приложение выполняет скрипт от имени пользователя и запоминает это
  до конца сессии;
- `"required"` — понятный отказ там, где sudo не разрешён. То, что приложение запускает само, — `detect` и сводка
  службы, оставленной в «Автоматически», — sudo не получает никогда (чтобы дать sudo на сервере, включите службу для
  этого сервера); в контейнере sudo не применяется — обработчик выполняется от пользователя `docker exec`;
- `"never"`.

## Контейнеры

`"service": {"containers": true}` позволяет пользователю указать, что служба работает в Docker-контейнере сервера
(«Где работает»). Тогда обработчик выполняется в `docker exec -i <контейнер> sh` (с путём к docker и sudo сервера), и
задана `SK_CONTAINER`. В контейнер секреты не передаются (командную строку контейнера на сервере можно прочитать);
обработчик, которому нужен секрет, завершается с сообщением.

## Скрипты, которые работают везде

- POSIX `sh`: dash в Debian, busybox ash в Alpine. Без `[[ ]]`, массивов, `local -n`, `echo -e`.
- awk — POSIX awk (mawk, busybox): без `gensub`, `asort`; `sub()` превращает число в текст — `x += 0` перед
  сравнением.
- `printf` лучше, чем `echo`; каждую переменную — в кавычки.
- `command -v` (или `sk_has`) перед инструментом, которого может не быть, с сообщением, что установить.
- Текстовые параметры доходят до скрипта: задайте им `pattern` в манифесте — приложение проверит значения до запуска.
- Обработчики должны быть быстрыми: страница ждёт свои обработчики данных.

## Попробовать

```sh
sshkipper-ext run list --settings '{"artisan": "/var/www/app/artisan"}'            # здесь
sshkipper-ext run list --ssh deploy@web-1                                            # на сервере (через ваш ssh)
sshkipper-ext run restart --ssh deploy@web-1 --item '{"id": "mail"}' --secret token=…
```

Пример: [examples/processes](../../examples/processes) — нагрузка, память, самые занятые процессы, страница процесса,
действия TERM/HUP/KILL с подтверждением, инструмент AI, блок автоматизации.
