# Модули SSHKipper

SSHKipper — нативный SSH-менеджер для macOS. **Модуль** добавляет в него одну интеграцию — службу ваших серверов
(очереди, набор юнитов systemd, свой бэкенд) или внешнюю систему:

- **службу** в «Службах» подключения, узел в дереве и раздел вкладки служб сервера;
- **страницы**, которые приложение рисует само из блоков UI-Kit (никакого HTML и WebView — JSON, из которого
  приложение строит свои контролы);
- **действия** в меню страницы — с вопросом перед всем, что меняет сервер;
- **инструменты AI**, которые агент приложения вызывает в рамках режима AI сервера;
- **блоки автоматизаций** для полотна автоматизаций;
- **настройки** в карточке подключения, наследуемые через папки.

Модули маленькие и атомарные: один модуль — одна вещь, как встроенные Docker, nginx, cron и базы данных.

## Два способа выполнения

| | `server` | `process` |
|---|---|---|
| Обработчики | shell-скрипты модуля | имена, на которые отвечает программа |
| Где выполняются | на сервере, через SSH-сессию приложения (бастионы, 2FA, контейнеры, `sudo -n`) | на этом Mac: программа, JSON-RPC через stdio |
| Для чего | смотреть и менять что-то на сервере | API, история, логика — всё, где нужен настоящий язык |
| Как достать сервер | они уже там | `host.exec(...)` — команду выполнит приложение по своей сессии |
| Язык | POSIX `sh` (без `jq`; JSON пишет прелюдия SDK) | любой; в SDK — среда на TypeScript для Node 24 |

Код модуля никогда не загружается в процесс приложения. Серверные скрипты нигде не устанавливаются: они едут с
каждым вызовом и ничего не оставляют.
